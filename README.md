# Клиентский брифинг

MVP по [prd.md](../prd.md): карточка-справка по клиенту перед выездом на встречу — ввод компании → веб-поиск по 6 блокам → LLM-суммаризация с честным «не найдено» → карточка со сводкой «Коротко» (стоп-факторы, рекомендации по взаимодействию, вопросы для встречи) + чек-лист готовности.

## Запуск

```bash
npm install
npm run dev
```

Открыть [http://localhost:3000](http://localhost:3000).

## Реальные данные vs демо-режим

Без API-ключей проект работает на детерминированных моках (и поиск, и LLM-суммаризация) — это видно по жёлтому баннеру «Демо-режим» над карточкой. Чтобы подключить реальный сбор данных, скопировать `.env.example` в `.env.local` и заполнить:

- `TAVILY_API_KEY` — веб-поиск ([tavily.com](https://tavily.com)).
- `ANTHROPIC_API_KEY` — LLM-суммаризация фрагментов по блокам (Claude, через tool-use для строгого JSON и защиты от галлюцинаций источников).

Каждый ключ подключается независимо: можно, например, включить только реальный поиск, оставив LLM на моке.

## Структура

- `lib/types.ts` — модель карточки (6 блоков, каждое поле — `{ value, found, source }`; блок 6 — список связанных компаний).
- `lib/search-queries.ts` — генерация поисковых запросов по блокам из PRD (раздел 6.2) + запросы на аффилированные/дочерние компании.
- `lib/search.ts` / `lib/mock-search.ts` — веб-поиск (Tavily или мок).
- `lib/llm.ts` / `lib/mock-llm.ts` — суммаризация фрагментов в карточку (Claude или мок).
- `lib/meeting-prep.ts` — панель «Коротко»: стоп-факторы, рекомендации по взаимодействию и вопросы для встречи. Считается программно из уже проверенных полей карточки (не отдельным LLM-вызовом), чтобы не добавлять новые непроверенные утверждения.
- `app/api/brief/route.ts` — единственный API-роут: вход → поиск → суммаризация → карточка.
- `components/BriefCard.tsx`, `components/FieldRow.tsx`, `components/Checklist.tsx` — вывод.

### Блоки карточки

1. Компания — название, сфера, дата образования, статус регистрации.
2. Налоговый статус — задолженность, налоговый режим.
3. ЛПР — ФИО, должность, срок, зона ответственности.
4. Контекст обслуживания — банк/подрядчики/партнёры.
5. Интересы ЛПР — хобби, публичные выступления, темы для small talk.
6. Связанные компании — аффилированные/дочерние/материнские структуры (тот же учредитель или руководитель).

Плюс сводка «Коротко» над блоками: краткое резюме, явные стоп-факторы, рекомендации по взаимодействию (с кого начать разговор, на что делать акцент) и вопросы, которыми можно закрыть пробелы прямо на встрече.

## Известные ограничения MVP (см. раздел 9, 11 PRD)

- Нет истории карточек и экспорта в PDF — не входит в MVP.
- Блок «Контекст обслуживания» изначально скуднее остальных — это ожидаемо по PRD, не баг.
- Суммы налогов не показываются — только бинарный статус задолженности, честно по разделу 9.
